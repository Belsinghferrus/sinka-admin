1. ROOT CAUSE OF INCORRECT SCROLLING BEHAVIOR
================================================================================

In the previous layout implementation:
1. `AdminLayout.jsx` defined the outermost layout wrapper with `min-h-screen`:
   `<div className="min-h-screen bg-stone-50 flex flex-col md:flex-row font-sans">`
   Because `min-h-screen` allows the element to grow indefinitely with long content
   (e.g., product creation forms, order tables, banner forms), the entire browser
   window/document body was forced to scroll vertically.

2. On desktop viewports (`md:` breakpoint and up), `Sidebar.jsx` was rendered with
   `md:static md:translate-x-0` without a fixed height constraint or independent
   scroll container. As a normal flow flex-item, scrolling the document body caused
   the sidebar to scroll upwards and disappear off the screen.

3. In `Header.jsx`, although `sticky top-0` was specified, the parent layout
   hierarchy allowed the whole window to scroll, causing inconsistent positioning,
   especially across mobile devices and when scrolling past the flex boundaries.

4. The main content container (`<main>`) lacked an explicit `overflow-y-auto`
   declaration, delegating all vertical scrolling to the viewport body rather than
   encapsulating it within the dedicated content pane.

================================================================================
2. FILES CHANGED
================================================================================

1. `src/layouts/AdminLayout.jsx`:
   - Replaced `min-h-screen` with `h-screen max-h-screen overflow-hidden flex`.
   - Constrained the main content column to `h-full overflow-hidden flex flex-col min-w-0`.
   - Made `<main>` the sole designated vertical scrolling container via
     `flex-1 overflow-y-auto p-4 sm:p-6 lg:p-8`.
   - Wrapped `<Outlet />` in `<div className="max-w-7xl w-full mx-auto">` so the
     scrollbar aligns seamlessly with the viewport edge while maintaining content
     centering and horizontal padding.

2. `src/components/layout/Sidebar.jsx`:
   - Updated desktop container classes to `md:static md:translate-x-0 md:h-full md:shrink-0`.
   - Added `shrink-0` to the top Brand Header (`h-16`) and bottom Admin User Panel
     to prevent vertical compression in flex contexts.
   - Preserved `flex-1 overflow-y-auto` on the navigation list (`<nav>`) so the menu
     can scroll independently if items exceed viewport height.
   - Preserved mobile slide-out behavior (`fixed top-0 bottom-0 left-0 z-50` with
     animated transform and backdrop).

3. `src/components/layout/Header.jsx`:
   - Added `shrink-0` to `<header>` to guarantee a rock-solid `h-16` (64px) height.
   - Retained `sticky top-0 z-30` within the non-scrolling content column.
   - Added route title resolvers for `/orders`, `/orders/:orderId`, and `/banners/*`
     to avoid generic "Admin Panel" fallback titles.

4. `tests/layout.test.js`:
   - Added automated architectural tests verifying viewport height locking,
     main-only overflow, sidebar fixed width and full height, and header shrinkage protection.

4. BEHAVIORAL SPECIFICATIONS
================================================================================

1. Top Navbar / Header:
   - Remains 100% static at the top of the content pane during vertical scrolling.
   - Zero vertical movement or displacement.
   - Exact preservation of `h-16` (64px), colors, typography, breadcrumb, and admin
     profile elements.
   - Zero visual shift or redesign.

2. Left Sidebar:
   - Remains 100% static on the left of the screen during main dashboard scrolling.
   - Exact preservation of `w-64` (256px), brand emblem, navigation items, icons,
     active states, and admin account footer.
   - Nav list (`<nav>`) scrolls independently if viewport height is reduced.
   - Zero visual shift or redesign.

3. Main-Content Scrolling:
   - Main dashboard content (`<main>`) is the single vertical scrolling region.
   - Page content flows underneath the fixed header and alongside the fixed sidebar.
   - No double scrollbars: body has zero scrollbars (`overflow: hidden`).
   - Scrollbar is neatly positioned on the right viewport edge.

4. Responsive / Mobile Behavior:
   - On screens `< md` (mobile and small tablets):
     * Sidebar behaves as an off-canvas drawer (`fixed z-50` with smooth translate animation).
     * Top header remains fixed at the top of the mobile viewport with menu hamburger button.
     * Main dashboard content scrolls smoothly below the mobile header.
     * Tapping menu opens the sidebar with semi-transparent backdrop (`z-40`).
