1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
The Sinka Admin Dashboard now features a complete, professional, production-grade
Homepage Hero Banner Management section seamlessly integrated with the backend REST
API and Cloudflare R2 object storage service under the dedicated `banners/` prefix.

Key Features & Achievements:
  1. Homepage Hero Banner Management:
     - Full CRUD operations with dedicated endpoints under `/api/admin/banners`.
     - Live carousel reordering controls (Move Up / Move Down) synchronized with
       the backend atomic batch reorder endpoint (`PATCH /api/admin/banners/reorder`).
     - Real-time active status toggle switches directly from the table with
       optimistic UI updates and rollback handling.
     - Keyword search across banner headline, subtitle, eyebrow, and CTA text.
     - Status filtering (All, Active, Inactive) and pagination controls.
     - Schedule status badges (Active Now, Scheduled, Expired, Inactive).
  2. Cloudflare R2 Banner Upload Integration:
     - Integrates with dedicated backend upload endpoint: POST /api/admin/upload/banners.
     - Supports JPEG, PNG, WebP, and AVIF up to 8 MB per file.
     - Single-image drag-and-drop zone with device file picker.
     - Real-time percentage upload progress bar, replace, and remove capabilities.
     - Direct backend deletion of uncommitted assets via DELETE /api/admin/upload/banners.
     - Zero credential leakage: R2 secret keys and access tokens remain exclusively
       on the backend; client stores only public CDN URLs and 'banners/' object keys.
  3. Customer Storefront Hero Carousel Preview:
     - High-fidelity preview component faithfully mirroring the customer storefront
       hero carousel (`HeroCarousel.jsx` in sinka-frontend).
     - Renders responsive 16:9 / 21:9 aspect ratio, dark gradient overlays, typography,
       uppercase eyebrow tags, rounded CTA buttons, mock navigation arrows, and trust bar.
     - Sticky real-time preview side-panel on the create/edit form that updates live
       as the administrator types or uploads photography.
     - Modal preview dialog directly accessible from the listing table.
  4. Banner Creation & Editing Workflows:
     - Unified, accessible form supporting creation (/banners/new) and editing
       (/banners/:id/edit).
     - 11 configurable fields:
       * Title (headline, 2-150 characters, required)
       * Subtitle / description (optional, max 300 characters)
       * Eyebrow label (optional, max 100 characters)
       * Banner image upload (Cloudflare R2, image URL + imageKey, required)
       * Image alt text (optional, defaults to title)
       * CTA button text (e.g. "Shop Collection", max 50 characters)
       * CTA destination URL / relative path (e.g. "/shop", max 500 characters)
       * Display order position (non-negative integer)
       * Active/inactive toggle switch
       * Optional start date & time (ISO format via datetime-local)
       * Optional end date & time (endDate >= startDate validation)
  5. Security & Isolation:
     - Uses 24-hour dedicated Admin JWT Bearer authentication via centralized apiClient.
     - Automatic FormData boundary generation (never overrides multipart Content-Type).
     - Customer storefront (sinka-frontend) and backend codebase remained untouched.

3. BACKEND API CONTRACT IMPLEMENTATION DETAILS
--------------------------------------------------------------------------------
Endpoint: POST /api/admin/upload/banners
  - Header: Authorization: Bearer <ADMIN_JWT>
  - Body: multipart/form-data (field name: 'image')
  - Response: { success: true, data: { key, url, contentType, size, originalName } }

Endpoint: DELETE /api/admin/upload/banners
  - Header: Authorization: Bearer <ADMIN_JWT>
  - Body: { "key": "banners/..." }
  - Response: { success: true, data: { key, deletedKey } }

Endpoint: GET /api/admin/banners
  - Header: Authorization: Bearer <ADMIN_JWT>
  - Query: { page, limit, search, isActive, sort: 'sortOrder:asc' }
  - Response: { success: true, data: { banners: [...], pagination: {...} } }

Endpoint: POST /api/admin/banners
  - Header: Authorization: Bearer <ADMIN_JWT>
  - Body: {
      title, subtitle, eyebrow, image, imageKey,
      altText, ctaText, ctaLink, sortOrder, isActive,
      startDate, endDate
    }
  - Response (201): { success: true, data: { banner: {...} } }

Endpoint: GET /api/admin/banners/:id
  - Header: Authorization: Bearer <ADMIN_JWT>
  - Response: { success: true, data: { banner: {...} } }

Endpoint: PATCH /api/admin/banners/:id
  - Header: Authorization: Bearer <ADMIN_JWT>
  - Body: (partial update payload)
  - Response: { success: true, data: { banner: {...} } }

Endpoint: PATCH /api/admin/banners/reorder
  - Header: Authorization: Bearer <ADMIN_JWT>
  - Body: { bannerOrders: [ { id, sortOrder }, ... ] }
  - Response: { success: true, data: { updatedCount: N } }

Endpoint: DELETE /api/admin/banners/:id
  - Header: Authorization: Bearer <ADMIN_JWT>
  - Response: { success: true, data: { deletedId } }
