3. MONGODB AGGREGATION PIPELINE (PERFORMANCE OPTIMIZED)
--------------------------------------------------------------------------------
File: `Sinka-backend/services/analytics.service.js`

Pipeline Structure:
1. $match stage:
   Filters by indexed `createdAt` date range:
   {
     createdAt: {
       $gte: startDate (midnight UTC of first day in range),
       $lte: endDate (23:59:59.999 UTC of today)
     }
   }
   Leverages existing compound indexes on `createdAt` without loading full order
   documents or customer subdocuments.

2. $group stage:
   Groups by formatted date string `YYYY-MM-DD` and tabulates status transitions:
   {
     _id: {
       $dateToString: { format: "%Y-%m-%d", date: "$createdAt", timezone: "UTC" }
     },
     total: { $sum: 1 },
     pending: {
       $sum: { $cond: [{ $eq: ["$status", "PENDING"] }, 1, 0] }
     },
     processing: {
       $sum: { $cond: [{ $in: ["$status", ["ACCEPTED", "PROCESSING", "PACKED"]] }, 1, 0] }
     },
     shipped: {
       $sum: { $cond: [{ $in: ["$status", ["SHIPPED", "OUT_FOR_DELIVERY"]] }, 1, 0] }
     },
     delivered: {
       $sum: { $cond: [{ $eq: ["$status", "DELIVERED"] }, 1, 0] }
     },
     cancelled: {
       $sum: { $cond: [{ $in: ["$status", ["CANCELLED", "REJECTED"]] }, 1, 0] }
     }
   }

3. Continuous Timeline Merge:
   Generates consecutive chronological dates (7, 14, or 30 days) and merges with
   the aggregation map. Any day with no orders is guaranteed to return 0 values
   so the chart displays a clean, unbroken timeline without gaps.
